応募情報を、確認しやすい形に。

Googleフォームは、採用やオーディションの応募受付にも使えます。回答をスプレッドシートに集められる一方で、自己紹介や志望動機などの長文、SNSや動画のリンクが並ぶと、応募者一人ひとりの情報を確認するための工夫が必要になります。

そこで、Google Apps Script（GAS）を使って、応募が届くたびに、回答内容を履歴書風のGoogleドキュメントへ自動整理する仕組みを開発しました。

この記事では、開発の背景と仕組み、自分の環境で試すための導入手順を紹介します。

開発の目的は、応募情報を履歴書のように読みやすく整理し、担当者が確認しやすい状態を作ることです。

応募情報には、氏名や居住国などの基本情報に加え、活動経験、得意分野、志望動機、SNS、自己紹介動画など、さまざまな種類の情報が含まれます。これらを、担当者が確認したい順番に並べた資料へ自動転記できれば、応募者ごとの情報をまとめる作業を減らせます。

今回の実装では、あらかじめGoogleドキュメントでテンプレートを作り、回答を所定の場所へ書き込む方法を採用しました。元の実装では、3つの表に情報を分けています。

資料の構成主な内容
基本情報・活動先氏名、ニックネーム、居住国、SNS、自己紹介、志望動機
スキル・経験語学、特技、経歴、配信経験
活動条件・補足契約状況、配信環境、活動予定、その他の回答

自由記述は、応募者が入力した文章をそのまま転記します。SNSや動画のURLにはリンクを設定し、資料から開けるようにしています。

フォーム送信から、資料の保存まで。

フォーム送信から資料の保存までを、Googleのサービス内でつなぎます。

処理の入口は、onFormSubmit(e)という関数です。

回答先スプレッドシートのフォーム送信トリガーから実行すると、e.valuesから回答内容、e.rangeから回答が記録された行などを取得できます。Google公式のイベント仕様で、受け取れる情報を確認できます。

回答の取得には、スプレッドシートのヘッダーを使っています。例えば、Your Nameを含むヘッダーを探し、その列の回答を氏名欄へ転記します。

列番号を直接書く方法に比べて、質問と処理の対応が読み取りやすくなります。ただし、質問名を変更した場合は、コード側の検索キーワードも確認する必要があります。

6項目の簡易版で、導入してみる。

元の実装は専用テンプレートの表構造に合わせているため、この記事では、新しく作ったフォームとテンプレートで試せるサンプルを紹介します。

準備するものは、Googleフォーム、回答先スプレッドシート、Googleドキュメントのテンプレート、保存先フォルダの4つです。

1. Googleフォームを作る

次の6つの質問を用意します。サンプルコードでは、この英語の質問名を検索します。自己紹介動画とYouTubeチャンネルには、https://から始まるURLを入力してください。

フォームの質問名入力する内容
Your Name氏名
Nick Nameニックネーム
Country of residence居住国
YouTube channelYouTubeチャンネルのURL
Self-Introduction自己紹介動画のURL
Motivation志望動機

2. 回答先スプレッドシートを設定する

Googleフォームの「回答」から、回答の保存先となるスプレッドシートを設定します。以降、GASはこのスプレッドシートから開きます。

3. Googleドキュメントでテンプレートを作る

単一タブのドキュメントに、セルを結合せず、2列6行の表を1つ作ります。見出し行は追加しません。

左列には、上から「氏名」「ニックネーム」「居住国」「YouTube」「自己紹介動画」「志望動機」と入力し、右列は回答欄として空けておきます。資料の見出しや表の幅、文字サイズなどは、Googleドキュメント上で調整できます。

4. 保存先フォルダとGASを設定する

Google Driveに資料の保存先フォルダを作ります。

回答先スプレッドシートの「拡張機能」から「Apps Script」を開き、サンプルコードを貼り付けます。TEMPLATE_DOC_IDとSAVE_FOLDER_IDは、自分のテンプレートとフォルダのIDへ変更してください。

ドキュメントIDはURLの/document/d/と/editの間、フォルダIDは/folders/の後ろにある文字列です。URLに?以降のパラメーターがある場合、その部分は含めません。

5. フォーム送信トリガーを追加する

コードを保存したら、Apps Scriptの「トリガー」から追加します。

この設定は、回答先スプレッドシート側のフォーム送信トリガーを使います。Googleフォーム側のトリガーとは、受け取るイベント情報が異なります。

インストール型トリガーは作成者のアカウントで動くため、そのアカウントがテンプレートをコピーでき、保存先にファイルを作成できる必要があります。Google公式のトリガー説明も参照してください。

サンプルコード

6項目の簡易版のコードです。コピーするか、ファイルをダウンロードしてApps Scriptに貼り付けてください。

sample.gs / Google Apps Script
ダウンロード 
function onFormSubmit(e) {
  const TEMPLATE_DOC_ID = 'YOUR_TEMPLATE_DOC_ID';
  const SAVE_FOLDER_ID = 'YOUR_SAVE_FOLDER_ID';

  if (!e || !e.range || !e.values) {
    throw new Error(
      '回答先スプレッドシートのフォーム送信トリガーから実行してください。'
    );
  }

  const sheet = e.range.getSheet();
  const header = sheet
    .getRange(1, 1, 1, sheet.getLastColumn())
    .getDisplayValues()[0];
  const rowData = e.values;

  // キーワードに該当する質問を探し、回答を取得する
  function getPartial(keyword) {
    const matches = [];

    for (let i = 0; i < header.length; i++) {
      if (header[i].toLowerCase().includes(keyword.toLowerCase())) {
        matches.push(i);
      }
    }

    if (matches.length !== 1) {
      throw new Error('質問を一意に特定できません: ' + keyword);
    }

    return String(rowData[matches[0]] || '');
  }

  // 配列の順番と、テンプレートの行の順番をそろえる
  const fields = [
    { keyword: 'Your Name', link: false },
    { keyword: 'Nick Name', link: false },
    { keyword: 'Country of residence', link: false },
    { keyword: 'YouTube channel', link: true },
    { keyword: 'Self-Introduction', link: true },
    { keyword: 'Motivation', link: false }
  ];

  const answers = fields.map(function (field) {
    return getPartial(field.keyword);
  });

  // 先頭行をヘッダーとして、回答行からファイル名を作る
  const numberStr = String(e.range.getRow() - 1).padStart(3, '0');

  const copiedFile = DriveApp.getFileById(TEMPLATE_DOC_ID).makeCopy(
    'data' + numberStr,
    DriveApp.getFolderById(SAVE_FOLDER_ID)
  );

  const doc = DocumentApp.openById(copiedFile.getId());

  try {
    const table = doc.getBody().getTables()[0];

    if (!table || table.getNumRows() !== fields.length) {
      throw new Error(
        'テンプレートの先頭に2列6行の表を用意してください。'
      );
    }

    for (let row = 0; row < fields.length; row++) {
      if (table.getRow(row).getNumCells() !== 2) {
        throw new Error(
          '表の各行はセルを結合せず2列にしてください。'
        );
      }
    }

    fields.forEach(function (field, row) {
      const value = answers[row];
      const cell = table.getCell(row, 1);

      cell.setText(value);

      if (value) {
        const text = cell.editAsText();
        text.setBold(true);

        if (field.link && /^https?:\/\//i.test(value)) {
          text.setLinkUrl(value);
        }
      }
    });
  } finally {
    doc.saveAndClose();
  }

  Logger.log('作成したドキュメントURL: ' + copiedFile.getUrl());
}

表への転記では、getCell(row, 1)で各行の右側のセルを指定しています。行と列は0から数えるため、列番号の1は2列目です。

セルへ文章を設定したあと、editAsText()で文字列を操作し、太字やリンクを設定しています。各メソッドは、Google公式のTableCellリファレンスで確認できます。

フォームから送信して、動作を確認する。

設定後は、実際にフォームからテスト回答を送信します。

Apps ScriptのエディタでonFormSubmitを直接実行すると、フォーム送信時の情報であるeが渡されません。動作確認は、フォームの回答画面から行ってください。

最初は架空の情報を入力し、次の点を確認します。

  • 回答がスプレッドシートに記録される
  • 指定フォルダにドキュメントが作成される
  • 右側の回答欄に、対応する内容が入っている
  • YouTubeと自己紹介動画のリンクが開ける
  • 長い志望動機でも、読みやすいレイアウトになっている

回答シートの2行目に記録された回答なら、ファイル名はdata001になります。これは回答行に基づく番号なので、行の削除や並べ替えを行う運用では、別の採番方法を検討してください。

資料が作成されない場合は、Apps Scriptの実行履歴を確認します。質問名の不一致、テンプレートの行・列数、ファイルID、アクセス権限が主な確認箇所です。

実際の業務へ導入する場合

このサンプルでは、フォーム回答からGoogleドキュメントを作成し、指定フォルダへ保存します。

業務で継続利用する場合は、作成した資料のURLを回答シートへ記録する、処理済みかどうかを管理する、エラー時に再処理できるようにする、といった機能も役立ちます。

サンプルには重複作成を防ぐ処理がないため、同じ回答を再処理するとコピーが追加されます。また、テンプレートの構造に誤りがある場合は、転記途中のコピーが残ることがあります。

生年月日から年齢を計算する機能を追加する場合は、日付形式と基準日を明確にして確認します。応募が集中する用途では、Apps Scriptの実行時間や利用上限も確認が必要です。

扱う情報に合わせて、生成資料と保存先フォルダを共有する範囲も設定してください。

フォームの回答整理や、資料作成の自動化をご相談ください。

今回の仕組みは、応募者プロフィールの作成に加え、申込情報の整理や面談前の確認資料などにも応用できます。

例えば、次のような調整が可能です。

  • 既存のGoogleフォームと帳票レイアウトに合わせる
  • 確認したい項目を、読みやすい順番に配置する
  • 作成した資料のURLを管理表へ記録する
  • PDF出力や担当者への通知を追加する

ご相談の際は、現在のフォーム項目、作成したい資料の見本、毎月のおおよその回答件数をお知らせください。業務の流れを伺い、必要な自動化の範囲をご提案します。
